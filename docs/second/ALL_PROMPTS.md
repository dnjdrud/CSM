# 마음이 닿는 집 — 시안 적용 개발 프롬프트

작성 기준: 2026-11-10, 녹음 전면 제거 + 기존 안내 이동 방식 유지 + 전환 효과 추가.

## 가장 중요한 사용자 정정

> 안내가 1.5초만 보이거나 자동으로 넘어가는 것이 아니다. 안내 순서와 버튼으로 넘기는 방식은 그대로 두고, 넘어가는 스타일에 1.5초씩 사라지고 나타나는 효과를 넣는다.

예: 현재 안내를 원하는 만큼 읽는다 → 기존 다음 버튼 클릭 → 현재 안내가 1.5초 동안 서서히 사라진다 → 기존 다음 안내로 교체 → 새 안내가 1.5초 동안 서서히 나타난다 → 사용자가 다음 버튼을 누를 때까지 그대로 보인다.

전환 효과의 합은 3초다. 별도 1.5초 대기·타이머·자동 진행은 없다. 기기의 동작 줄이기 설정에서는 즉시 교체한다. 다음/이전 버튼, 화면 구성, 안내 단계 수를 효과 때문에 바꾸지 않는다.

## 디자인 기준 이미지

1. 디자인 제안 01: 로그인·비밀번호·첫 안내·짧은 편지·사용 안내·일곱 방 목록.
   https://chatgpt.com/library?file_id=libfile_da873a40e1408191ac33529f76501d35&account_id=personal
2. 디자인 제안 02: 새로운 입장 안내 + 일곱 방.
   https://chatgpt.com/library?file_id=libfile_0206ccc6199c81919e83d04c4d776641&account_id=personal
3. 글쓰기·개인글·공유 확인·대화 제안·관리자는 위 두 시안의 공통 디자인을 확장한다. 별도 03 이미지가 제공되지 않았다면 생성·승인되었다고 간주하지 않는다.

위 링크는 사용자 열람용이다. 개발 도구가 접근하지 못하면 이미지를 해당 작업에 첨부한다. 시안 전체를 배경으로 깔아 화면을 흉내 내지 않는다. 실제 HTML 입력·버튼·접근성 구조로 구현한다. 본문은 읽기 쉬운 고딕체, 제목만 절제된 명조체를 사용할 수 있다.

## 실행 순서

01 조사 → 02 공통 디자인 → 03 전환 효과 → 04 로그인·안내 → 05 방 목록·입장 → 06 일곱 방 → 07 글·보관함 → 08 대화 제안 → 09 관리자 → 10 통합 검증.

각 파일은 개발 에이전트에 순서대로 전달할 독립 실행 프롬프트다. 01에서 발견한 차이를 이후 단계에 반영한다. 새로운 에이전트에서는 공통 확정사항과 앞 단계 변경 내역을 같이 읽힌다.

## 범위

# 01 — 현재 구현 조사와 변경 범위 확정

Family 프로젝트의 UI 개편을 시작한다. 구현 파일과 요구사항을 실제로 대조하고 필요한 개선을 바로 준비하라.

1. AGENTS.md, docs 문서 전체, package.json, DEPLOYMENT.md와 설치된 Next.js 문서를 읽어라. 현재 PostgreSQL 버전과 과거 SQLite 버전을 혼동하지 마라.
2. src/app의 모든 page.tsx와 API 경로, src/components, src/content, src/lib, src/server, tests, scripts를 조사하라. 각 화면을 구현/부분 구현/미구현으로 구분하고 근거 파일을 남겨라.
3. 실제 기준 경로: /login, /login/[role], /welcome, /welcome/letter, /welcome/guide, /rooms, /rooms/[roomId], /notes, /admin/login, /admin, /admin/letters, /admin/letters/[id], /admin/proposals, /admin/content, /admin/content/[key]. 글쓰기·개인 보관함·대화 제안은 컴포넌트 안의 상태 화면도 조사한다.
4. EntryGate.tsx, RoomFlow.tsx, gate-machine.ts, gate-rules.ts, room-access.ts와 입장 API가 녹음 없는 읽기 준비로 전환되었는지 확인하라. 남은 녹음 UI나 getUserMedia/MediaRecorder 호출이 있으면 제거하라. 기존 세션/방/방문 단기 권한은 보존한다.
5. 기존 다음/이전 클릭과 이동 단계를 목록화한다. 이 목록이 애니메이션 적용 전후 같아야 한다. 안내 문장을 새 페이지로 잘게 나누지 마라.
6. CSS 토큰과 하드코딩된 색, 공통 버튼/카드/오류/본문의 중복, 글씨 확대 처리, focus, safe-area, 저속 네트워크 처리를 조사하라.
7. 사용자 비밀번호·키·실제 글은 출력하지 말고 설정 여부만 확인한다. DB 초기화나 운영 데이터 수정 없이 기준 체크를 실행한다.

산출물: docs/UI_REDESIGN_STATUS.md에 화면별 근거, 작업 순서, 실제 기준 검증 결과를 기록하고 다음 프롬프트가 사용할 공통 컴포넌트와 수정 위치를 정리하라. 이 문서만 쓰고 끝내지 말고 필요한 녹음 잔재 정리도 완료하라.

## 모든 작업에 적용할 확정사항

- 현재 Family의 실제 코드와 AGENTS.md, docs/00~06, README, DEPLOYMENT.md를 읽고 시작한다. 설치된 Next.js 문서를 확인한다. 문서 존재를 구현 완료의 증거로 삼지 않는다.
- 최신 배포용 소스는 Supabase PostgreSQL을 사용하는 Family 작업본이다. 기존 SQLite 원본으로 덮어쓰지 않는다. 사용자 수정, 기존 인증·글·암호화·콘텐츠 검토 기능을 보존한다.
- **녹음 기능은 전부 폐지했다.** 마이크 허용 요청, 녹음·재생·음성 분석·음성 파일·녹음 대체 타이머를 만들지 않는다. 과거 00~06의 녹음 필수 지시보다 이 변경이 우선한다. Permissions-Policy의 microphone=()를 유지한다.
- **안내 순서와 다음/이전 버튼으로 넘기는 방식은 기존 그대로 유지한다. 바꾸는 것은 전환 스타일이다.** 다음 버튼을 누르기 전에는 현재 안내가 계속 보인다. 버튼으로 넘길 때 현재 안내 fade-out 1.5초 → 기존 다음 안내로 교체 → fade-in 1.5초. 1.5초만 보여주고 넘기는 기능, 자동 넘김, 문장별 자동 재생, 새 슬라이드 단계 추가를 만들지 않는다.
- 시안은 화면 구성·색·그림 분위기의 참고다. 이미지 속 편지와 수치, 글, 입력칸 수는 확정 요구사항이 아니다. 특히 아빠 8자리·엄마 4자리 비밀번호를 시안의 4칸 때문에 바꾸지 않는다.
- 큰 글씨와 쉬운 한국어, 본문 20px 이상·제목 28~32px·버튼 높이 60px 이상을 유지한다. 작은 글씨로 꾸미지 않는다. 로그인 후 안내를 나중에 다시 열 수 있어야 한다.
- 엄마/아빠/아들 계정과 데이터 분리, HttpOnly/Secure/SameSite 서명 세션, 로그인 제한, CSRF/Origin 검사, 서버 권한 확인, no-store, 검색 차단을 유지한다. 기기 기억·자동 로그인·공개 가입을 추가하지 않는다.
- 개인글 제목/본문/개인 비밀번호/복호화 키를 서버·로그·분석에 보내지 않는다. 개인글은 Web Crypto 암호문만 영속 저장하며 실패 시 평문으로 대체하지 않는다. 관리자는 공유글만 선택해서 본다.
- 방 본문은 로그인과 해당 방문의 서버 권한 확인 후에만 반환한다. 애니메이션을 이유로 미리 HTML/RSC/API에 포함하지 않는다. 녹음 폐지는 인증 폐지가 아니다.
- 감정·읽음·체류시간·입장 횟수를 기록하거나 점수화하지 않는다. 결혼 승낙·사과·찬성을 입장 조건으로 만들지 않는다. 없는 사실·예산·상환 실적·날짜를 만들지 않는다.
- 편지와 카드의 초안/검토/게시 상태를 유지한다. 시안 구현 때문에 초안을 자동 게시하지 않는다. 외부 메시지 발송·자동 약속 확정은 하지 않는다.
- 실제 배포는 별도 요청이 있는 경우에만 진행한다. 이 프롬프트 묶음을 실행한다는 이유로 운영 데이터를 초기화하거나 기존 Supabase/Vercel 프로젝트를 삭제하지 않는다.

## 작업 완료 보고

변경 파일, 실제 구현 내용, 실행한 검증과 결과, 남은 수동 확인을 구분해 짧게 보고한다. 실행하지 않은 검증을 통과라고 쓰지 않는다. 사용자에게 다음 단계로 진행할지 반복 확인하지 말고 이 단계에서 승인된 구현과 검증을 완료한다.

# 02 — 공통 디자인 시스템과 화면 틀

시안 01·02의 크림색·햇빛·식물·편지 분위기를 실제 UI로 구현하라. 기존 큼직한 사용성을 유지하면서 현재의 전체 고동색 배경을 밝고 정돈된 화면으로 바꾼다.

대상: src/app/globals.css, components/AppShell.tsx, ui.tsx, TextSizeControl.tsx, 공통 이미지 컴포넌트. 실제 구조를 읽고 파일을 추가/분리하라.

- 출발 토큰: 배경 #FAF7F0, 본문 #382B24, 표면 #FFFDFA, 포인트 sage #78866B, terracotta #B87557. 포인트 색은 후보일 뿐이다. 흰색 글씨와 대비가 부족하면 버튼색을 더 어둡게 보정하고 사용색별 명암비를 계산하라. 일반 텍스트 4.5:1 이상, 큰 텍스트·UI 경계 3:1 이상을 검증한다.
- 메인 버튼 하나는 진한 terracotta 또는 진한 sage, 보조 버튼은 밝은 바탕+선명한 글씨/테두리. 과한 그림자, 광택, 그라데이션, 점수 배지, 이모지 나열을 피한다.
- 본문은 system Korean sans 또는 검증된 로컬 고딕체. 제목에만 로컬 명조체를 선택적으로 사용한다. 외부 폰트 CDN 요청은 만들지 않는다. 폰트 확보가 안 되면 폴백을 사용한다.
- 20px 본문, 28~32px 제목, 본문 line-height 1.7~1.85, 60px 이상 버튼. 확대는 rem 기준으로 함께 커져야 한다. 360px에서 CTA 문구가 두 줄이어도 높이가 유지되어야 한다.
- 상단은 집 아이콘+서비스명, 필요한 뒤로/방 목록을 명확히 노출한다. 시안의 햄버거 메뉴에 필수 이동을 숨기지 않는다. 글씨 확대·나가기 수단을 계속 찾기 쉽게 둔다.
- 모바일 가로 여백 20~24px, 좁은 화면에서는 16px까지. 콘텐츠 최대 폭은 현재 모바일 읽기 폭을 유지한다. safe-area-inset-bottom을 반영한다. 하단 고정 CTA를 쓰면 본문과 키보드 입력을 가리지 않게 여유 공간을 확보한다.
- 이미지 테마: 햇빛 드는 집, 열린 창, 봉투, 새싹, 노트, 두 잔, 두 의자, 식탁. 승인된 일반 일러스트만 사용하고 가족 실사진이나 개인정보를 넣지 않는다. 이미지 안에 UI 본문을 굽지 않는다.
- 이미지 제공이 안 되면 승인되지 않은 임의 외부 이미지를 가져오지 말고 동일 비율의 단순한 장식 자리표시자를 사용하며 남은 자산을 명시한다. 시안 보드 전체를 crop해서 실서비스 이미지로 쓰지 않는다.
- next/image 사용 규칙을 설치 문서에서 확인하고 이미지 크기/비율을 지정한다. 장식 이미지는 alt 빈 값, 의미 있는 이미지는 짧은 대체 설명. 이미지 실패해도 읽기와 이동이 가능해야 한다.
- 오류·disabled·성공·empty·로딩·focus 상태도 공통화한다. 서비스 전체 색 전환으로 기존 text-btn처럼 밝은 글씨를 기대한 클래스가 안 보이지 않는지 전수 점검한다.

검증: 로그인·긴 본문·입력 폼·관리자 대표 화면에서 360/390/430px, 기본/최대 글씨, 키보드 포커스, 명암비, 이미지 실패를 확인한다. 디자인 구현만으로 개인정보 저장 모델을 바꾸지 않는다.

# 03 — 안내 이동 방식은 유지하고 전환 스타일만 변경

사용자 정정이 핵심이다. **안내 순서·단계 수·다음/이전 버튼·클릭 시점은 기존 그대로다. 이동할 때의 시각적 전환만 변경한다.** 안내를 1.5초만 표시하거나 자동으로 넘기는 기능은 금지한다.

대상: 공통 FadeTransition 또는 GuideTransition 컴포넌트, globals.css, RoomFlow, 첫 안내/편지/사용 안내 등 실제 다음/이전 이동 지점. 기존 상태를 읽고 최소한으로 통합한다.

정확한 동작:
1. 처음 안내는 사용자가 원하는 만큼 계속 읽는다. 자동 진행 타이머는 없다.
2. 기존 다음/이전 버튼을 클릭하면 현재 안내 opacity 1→0을 1500ms 동안 ease-in-out으로 실행한다.
3. fade-out 완료 시점에 기존 로직대로 다음/이전 안내로 바꾼다. 안내를 나누거나 합치지 않는다.
4. 새 안내 opacity 0→1을 1500ms 동안 ease-in-out으로 실행한다.
5. 새 안내는 다음 사용자 클릭 전까지 그대로 보인다. 효과 이외의 대기시간을 추가하지 않는다.

구현 조건:
- 공통 상태는 idle/exiting/entering 정도로 제한한다. 버튼 연타로 중복 진행하거나 두 단계 건너뛰지 않게 한다. 전환 중 해당 다음/이전 동작을 잠시 비활성화하고 요청당 한 번만 실행한다.
- transform 확대·회전·옆으로 슬라이드·깜빡임 없이 opacity 중심으로 구현한다. 문장별 타자 효과나 강제 낭독을 넣지 않는다.
- prefers-reduced-motion: reduce에서는 두 애니메이션과 지연을 모두 생략한다. 단지 CSS만 0으로 바꾼 채 JS 타이머 3초를 기다리지 않는다.
- animationend/transitionend를 쓴다면 대상·속성을 검증하고, 누락 시 안전한 완료 처리를 제공한다. timeout을 쓴다면 unmount·새 이동·로그아웃 때 취소한다. 늦은 콜백이 이전 화면을 복구하지 못하게 한다.
- 새로운 안내가 나타난 뒤 제목 또는 main으로 포커스를 옮긴다. 사라진 안내의 버튼/입력은 키보드와 스크린리더에서 중복 노출하지 않는다. 현재 안내와 다음 안내를 동시에 aria-live로 읽히지 않는다.
- 같은 안내 안의 입력·비밀번호 표시·글씨 확대·오류 메시지·모달 토글에는 3초 전환을 적용하지 않는다. 입력 내용이 애니메이션 때문에 초기화되지 않게 한다.
- 일반 방 이동/뒤로/로그아웃의 의미를 바꾸지 않는다. 특히 로그아웃·세션 만료·접근 거절 때는 민감 본문을 즉시 제거하며 fade-out을 기다리지 않는다.
- Next 서버 페이지를 전부 client component로 바꾸지 않는다. 미인증·미입장 본문을 다음 화면 애니메이션용 prop으로 미리 보내지 않는다. 이미 권한이 있는 화면의 시각적 전환만 처리한다.
- 서버/네트워크 응답을 기다리는 시간이 있다면 그 시간과 시각 효과 시간을 구분한다. 네트워크 실패 시 기존 안내에서 다시 시도할 수 있게 하고 빈 화면에 갇히지 않게 한다.
- 그림이나 높이가 바뀌어도 겹침·가로 스크롤을 만들지 않는다. 긴 안내를 읽은 뒤 넘기면 새 안내 시작으로 스크롤을 맞추되 동작 줄이기에서는 부드러운 스크롤을 생략한다.

검증: 클릭 전 장시간 같은 안내 유지, 다음/이전 각 1500ms out+1500ms in, 연타 한 번만 진행, 전환 중 unmount/뒤로/세션 만료, reduced-motion 무지연, 포커스와 읽기 순서, 폼 값 보존. 모의 타이머 단위 검사와 실제 브라우저 대표 이동 검사를 함께 수행한다. 기존 이동 단계 목록과 적용 후 목록이 동일함을 확인한다.

5. 앞으로의 삶: 이유/알고 있는 현실/함께 준비할 생활/미정/참여 희망의 다섯 카드. 찬성 강요나 여자친구 개인정보 노출 없이 걱정·응원·나중에 선택을 둔다.

# 08 — 대화 제안과 제안 내역

시안 02의 7번 방과 시안 01·02의 공통 디자인을 확장한 추가 화면의 대화 제안 화면을 적용한다. 대상 ProposalForm.tsx, MyProposals.tsx, RoomBody.tsx, server/proposals.ts 및 실제 관련 API.

- 전화·만남·동행 제안 폼은 선택한 방법을 상단에 분명히 표시한다. 희망 일시·장소·동행인은 선택이며 빈 값도 제출할 수 있다. 메시지 길이 제한과 안전한 텍스트 렌더링을 유지한다.
- 시간은 Asia/Seoul 기준임을 보이게 안내하고 날짜/시각을 브라우저 현지시간과 혼동하지 않는다. 과거 시각·존재하지 않는 날짜는 클라이언트와 서버에서 검증한다.
- 제출 전 요약: 방법/작성한 선택 항목/메시지를 부모가 확인한다. 버튼은 ‘제안 보내기’. 아들이 수락 전에는 ‘제안 중’으로 표시하고 자동으로 약속을 확정하지 않는다.
- 내 제안 목록은 제안 중/수락/다른 시간 제안/취소 등 실제 서버 상태를 정확히 표현한다. 취소와 취소 확인을 제공한다. 다른 시간 제안이 자동 수락으로 표시되지 않게 한다.
- 외부 문자·카카오톡·메일·캘린더 발송은 없다. 미리보기나 알림에 본문을 자동 노출하지 않는다. 다른 부모의 제안은 조회하지 못한다.

- 사전 안내 후 명시적 읽기 선택, 방1 바로 입장, 본문 입장 전 미노출, 사용자/방/세션/방문 교차·재사용 토큰 거부, 관리자 부모 권한 우회 없음.
- 인증 전 HTML/RSC/API/정적 번들에 민감정보 없음. 초안 게시 전 미노출. 상태 복원이나 애니메이션 캐시에 다른 계정 내용 없음.
- 개인글 제목/본문은 DB에 평문 없음. 개인 비밀번호·키·평문 서버 요청/로그 없음. 부모 교차 접근 차단, 관리자 개인글 접근 불가, 공유글 최종 확인, 소유자 편집·삭제.
- 대화 제안 서울시간·과거 검증·제안 중/수락/다른 시간/취소, 외부 발송·자동 확정 없음.
- 없는 수치·실적·일정·발언 생성 없음. 부모 지원 월 70만원 항목을 사용하지 않는다.

브라우저 검사는 실제 페이지→API→DB→화면을 연결해 확인한다. 운영에서 테스트가 꼭 필요하면 명확한 임시 공유글만 만들고 제거하며 개인 보관함 비밀번호나 실제 초안을 바꾸지 않는다. 테스트 DB 사용이 우선이다. 실제 iPhone Safari/Android Chrome을 쓰지 못했다면 미확인으로 남긴다. 녹음은 삭제했으므로 마이크 수동 테스트를 남은 과제로 쓰지 않는다.

최종 산출: README/DEPLOYMENT/화면별 검증표 갱신, 이미지 자산 목록과 출처, 실제 색 대비표, 변경 파일과 남은 수동 확인, 결과가 포함된 인수인계. 사용자가 배포를 별도 승인한 경우에만 운영 반영하고 URL·배포 상태·기본 동작을 확인한다. 디자인 개발 완료와 단순 시안 생성/문서 작성을 혼동하지 않는다.

## 모든 작업에 적용할 확정사항

- 현재 Family의 실제 코드와 AGENTS.md, docs/00~06, README, DEPLOYMENT.md를 읽고 시작한다. 설치된 Next.js 문서를 확인한다. 문서 존재를 구현 완료의 증거로 삼지 않는다.
- 최신 배포용 소스는 Supabase PostgreSQL을 사용하는 Family 작업본이다. 기존 SQLite 원본으로 덮어쓰지 않는다. 사용자 수정, 기존 인증·글·암호화·콘텐츠 검토 기능을 보존한다.
- **녹음 기능은 전부 폐지했다.** 마이크 허용 요청, 녹음·재생·음성 분석·음성 파일·녹음 대체 타이머를 만들지 않는다. 과거 00~06의 녹음 필수 지시보다 이 변경이 우선한다. Permissions-Policy의 microphone=()를 유지한다.
- **안내 순서와 다음/이전 버튼으로 넘기는 방식은 기존 그대로 유지한다. 바꾸는 것은 전환 스타일이다.** 다음 버튼을 누르기 전에는 현재 안내가 계속 보인다. 버튼으로 넘길 때 현재 안내 fade-out 1.5초 → 기존 다음 안내로 교체 → fade-in 1.5초. 1.5초만 보여주고 넘기는 기능, 자동 넘김, 문장별 자동 재생, 새 슬라이드 단계 추가를 만들지 않는다.
- 시안은 화면 구성·색·그림 분위기의 참고다. 이미지 속 편지와 수치, 글, 입력칸 수는 확정 요구사항이 아니다. 특히 아빠 8자리·엄마 4자리 비밀번호를 시안의 4칸 때문에 바꾸지 않는다.
- 큰 글씨와 쉬운 한국어, 본문 20px 이상·제목 28~32px·버튼 높이 60px 이상을 유지한다. 작은 글씨로 꾸미지 않는다. 로그인 후 안내를 나중에 다시 열 수 있어야 한다.
- 엄마/아빠/아들 계정과 데이터 분리, HttpOnly/Secure/SameSite 서명 세션, 로그인 제한, CSRF/Origin 검사, 서버 권한 확인, no-store, 검색 차단을 유지한다. 기기 기억·자동 로그인·공개 가입을 추가하지 않는다.
- 개인글 제목/본문/개인 비밀번호/복호화 키를 서버·로그·분석에 보내지 않는다. 개인글은 Web Crypto 암호문만 영속 저장하며 실패 시 평문으로 대체하지 않는다. 관리자는 공유글만 선택해서 본다.
- 방 본문은 로그인과 해당 방문의 서버 권한 확인 후에만 반환한다. 애니메이션을 이유로 미리 HTML/RSC/API에 포함하지 않는다. 녹음 폐지는 인증 폐지가 아니다.
- 감정·읽음·체류시간·입장 횟수를 기록하거나 점수화하지 않는다. 결혼 승낙·사과·찬성을 입장 조건으로 만들지 않는다. 없는 사실·예산·상환 실적·날짜를 만들지 않는다.
- 편지와 카드의 초안/검토/게시 상태를 유지한다. 시안 구현 때문에 초안을 자동 게시하지 않는다. 외부 메시지 발송·자동 약속 확정은 하지 않는다.
- 실제 배포는 별도 요청이 있는 경우에만 진행한다. 이 프롬프트 묶음을 실행한다는 이유로 운영 데이터를 초기화하거나 기존 Supabase/Vercel 프로젝트를 삭제하지 않는다.

## 작업 완료 보고

변경 파일, 실제 구현 내용, 실행한 검증과 결과, 남은 수동 확인을 구분해 짧게 보고한다. 실행하지 않은 검증을 통과라고 쓰지 않는다. 사용자에게 다음 단계로 진행할지 반복 확인하지 말고 이 단계에서 승인된 구현과 검증을 완료한다.
