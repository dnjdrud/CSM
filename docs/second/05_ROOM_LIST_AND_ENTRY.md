# 05 — 일곱 방 목록과 녹음 없는 입장 안내

시안 01의 방 목록과 시안 02의 입장 안내를 구현한다. 방을 순서대로 클리어시키는 구조를 만들지 않는다.

대상: app/rooms/page.tsx, rooms/[roomId]/page.tsx, RoomFlow.tsx, EntryGate.tsx, content/types.ts·rooms.ts, gate-machine.ts·gate-rules.ts·gate-visit.ts, server/room-access.ts, api/rooms의 attempt/enter/leave.

- 방 목록은 ‘오늘은 어떤 마음이세요?’처럼 부담 없는 제목, 짧은 안내, 일곱 개의 큰 카드로 구성한다. 번호는 이름을 찾기 위한 용도다. 완료 표시·방문률·잠금 해제 순서·진도·읽음 배지를 두지 않는다.
- 방별 그림: 1 노트/압화, 2 편지/창가, 3 새싹, 4 노트/책상, 5 두 잔/식탁, 6 두 의자, 7 대화 테이블. 실제 부모 사진은 쓰지 않는다.
- 방1은 기존대로 바로 열리고 글 작성으로 갈 수 있다. 방2~7은 기존 방별 사전 안내·편지·질문 흐름을 그대로 거친다. 방3 생각 적기는 선택이며 거절해도 진행할 수 있다.
- 마지막 입장 준비 화면 제목: ‘지금 바로 답하지 않으셔도 괜찮아요’. 본문: ‘어떤 마음으로 오셨든 괜찮아요. 편하시다면 어깨의 힘을 풀고, 숨을 한 번 천천히 쉬어보세요.’ / ‘오늘은 서로의 생각을 조금 알아보는 것만으로 충분해요. 동의하거나 어떤 결정을 내리지 않으셔도 돼요.’ / ‘마음이 무거우면 언제든 쉬었다 오세요.’
- 버튼은 [조금 읽어볼게요], [나중에 올게요], 필요할 때 [앞 안내로 돌아가기]. 숨쉬기 횟수·시간을 측정하지 않는다. 감정 고르기·다짐 입력·체크박스 동의·서약·사과·녹음을 필수로 만들지 않는다.
- 기존 entryPhrase가 있다면 조용히 읽는 방별 소개 문장으로만 사용한다. 부모가 말한 진심이나 입장 동의 증거라고 저장하지 않는다.
- 서버는 여전히 로그인 사용자·세션·방·이번 방문·일회성 시도를 확인한 뒤 본문과 단기 grant를 반환한다. recordedMs/재생 시간 조건을 제거하고 explicit confirmed:true를 확인한다. 타 계정/방/세션/방문의 토큰과 재사용은 거절한다. 녹음 테이블이나 감정 저장 필드를 추가하지 않는다.
- 마이크 API와 지원 여부 검사·녹음 에러·Blob/Object URL·음성 UI·필수 청취 상태가 런타임 소스에서 사라졌는지 확인한다. microphone=()를 유지한다.
- 새로고침·직접 URL·새 방 입장에서는 해당 준비 흐름을 보여준다. 단순히 다른 앱을 잠시 보거나 화면을 잠갔다 돌아온 일을 감정 준비 실패로 취급하지 않는다. 일반 세션·인증 보안은 유지한다.
- EntryGate에서 RoomBody로 넘어갈 때 컴포넌트 unmount cleanup이 방금 받은 grant를 삭제하지 않게 한다. 실제 방을 떠날 때만 방문을 정리한다. 늦은 이전 요청이 새 방문을 취소하지 않게 한다.

검증: 마이크 권한을 거부한 환경과 mediaDevices 없는 환경에서도 정상 입장, 방1 즉시 입장, 방2~7 사전 안내 유지, 토큰 교차/재사용 차단, 입장 전 본문 비노출, 나중에 버튼, 연타/통신 실패/이탈/뒤로/새로고침, 입장 후 글 작성에 grant 유효.

## 모든 작업에 적용할 확정사항

- 현재 Family의 실제 코드와 AGENTS.md, docs/00~06, README, DEPLOYMENT.md를 읽고 시작한다. 설치된 Next.js 문서를 확인한다. 문서 존재를 구현 완료의 증거로 삼지 않는다.
- 최신 배포용 소스는 Supabase PostgreSQL을 사용하는 Family 작업본이다. 기존 SQLite 원본으로 덮어쓰지 않는다. 사용자 수정, 기존 인증·글·암호화·콘텐츠 검토 기능을 보존한다.
- **녹음 기능은 전부 폐지했다.** 마이크 허용 요청, 녹음·재생·음성 분석·음성 파일·녹음 대체 타이머를 만들지 않는다. 과거 00~06의 녹음 필수 지시보다 이 변경이 우선한다. Permissions-Policy의 microphone=()를 유지한다.
- **안내 순서와 다음/이전 버튼으로 넘기는 방식은 기존 그대로 유지한다. 바꾸는 것은 전환 스타일이다.** 다음 버튼을 누르기 전에는 현재 안내가 계속 보인다. 버튼으로 넘길 때 현재 안내 fade-out 1.5초 → 기존 다음 안내로 교체 → fade-in 1.5초. 1.5초만 보여주고 넘기는 기능, 자동 넘김, 문장별 자동 재생, 새 슬라이드 단계 추가를 만들지 않는다.
- 시안은 화면 구성·색·그림 분위기의 참고다. 이미지 속 편지와 수치, 글, 입력칸 수는 확정 요구사항이 아니다. 특히 아빠 8자리·엄마 4자리 비밀번호를 시안의 4칸 때문에 바꾸지 않는다.
- 큰 글씨와 쉬운 한국어, 본문 20px 이상·제목 28~32px·버튼 높이 60px 이상을 유지한다. 작은 글씨로 꾸미지 않는다. 로그인 후 안내를 나중에 다시 열 수 있어야 한다.
- 엄마/아빠/아들 계정과 데이터 분리, HttpOnly/Secure/SameSite 서명 세션, 로그인 제한, CSRF/Origin 검사, 서버 권한 확인, no-store, 검색 차단을 유지한다. 기기 기억·자동 로그인·공개 가입을 추가하지 않는다.
- 개인글 제목/본문/개인 비밀번호/복호화 키를 서버·로그·분석에 보내지 않는다. 개인글은 Web Crypto 암호문만 영속 저장하며 실패 시 평문으로 대체하지 않는다. 관리자는 공유글만 선택해서 본다.
- 방 본문은 로그인과 해당 방문의 서버 권한 확인 후에만 반환한다. 애니메이션을 이유로 미리 HTML/RSC/API에 포함하지 않는다. 녹음 폐지는 인증 폐지가 아니다.
- 감정·읽음·체류시간·입장 횟수를 기록하거나 점수화하지 않는다. 결혼 승낙·사과·찬성을 입장 조건으로 만들지 않는다. 없는 사실·예산·상환 실적·날짜를 만들지 않는다.
- 편지와 카드의 초안/검토/게시 상태를 유지한다. 시안 구현 때문에 초안을 자동 게시하지 않는다. 외부 메시지 발송·자동 약속 확정은 하지 않는다.
- 실제 배포는 별도 요청이 있는 경우에만 진행한다. 이 프롬프트 묶음을 실행한다는 이유로 운영 데이터를 초기화하거나 기존 Supabase/Vercel 프로젝트를 삭제하지 않는다.

## 작업 완료 보고

변경 파일, 실제 구현 내용, 실행한 검증과 결과, 남은 수동 확인을 구분해 짧게 보고한다. 실행하지 않은 검증을 통과라고 쓰지 않는다. 사용자에게 다음 단계로 진행할지 반복 확인하지 말고 이 단계에서 승인된 구현과 검증을 완료한다.
