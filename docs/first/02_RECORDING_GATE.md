# 2단계 — 모든 재입장에 적용되는 녹음 게이트
가장 중요한 독립 구현 작업이다.
## 상태
prelude → ready → requestingPermission → recording → recorded → playing → listened → confirmed → room
실패/재녹음/이탈 시 다음 상태 권한을 적절히 초기화한다. 1번 방은 예외.
## 정확한 UX
방 선택→방별 안내·사전 편지·질문→마지막 안내 ‘아래 버튼을 누르고 표시된 말을 말씀해 주세요’→[녹음 시작하기]→[녹음 끝내기]→[내 목소리 듣기]→전체 재생 완료 뒤 [이 마음으로 들어가기].
‘다시 녹음하기’, ‘방 목록으로’ 상시 제공. 안내에는 녹음이 아들에게 전달되지 않고 입장 확인에만 쓰인다고 명시.
## 구현
MediaDevices/getUserMedia와 MediaRecorder 지원/MIME을 탐지. iOS Safari/Android Chrome 대응. HTTPS 또는 localhost 필요 안내. 권한 거부/마이크 없음/장치 사용 중/빈 녹음/재생 실패 시 재시도와 복귀만. 대체 텍스트 동의 금지.
최소 녹음 길이는 실수로 누른 경우만 방지하는 짧은 값으로 설정. 무음 여부/문구 일치/실제 청취를 검증했다고 주장하지 않는다. 음성인식/외부 전송 금지.
오디오 파일은 Blob으로 메모리에서만. 전체 재생 완료 전 확인 버튼 금지. 탐색바/배속/끝으로 건너뛰기 없음. 중단 후 다시 듣기는 처음부터. ended 하나만으로 충분히 들었다고 처리하지 않도록 재생 시간·seek 이벤트와 상태 확인. 접근성 제공. 웹 클라이언트 조작을 완벽히 차단한다고 주장하지 않는다.
재녹음 시 기존 listened/confirmed 무효. 나가기/로그아웃/재진입/새로고침 시 입장 토큰 무효, 미디어 트랙 중지, Object URL 해제. 입장 후 녹음 즉시 폐기.
서버는 현재 사용자·방·세션·이번 시도에 연결된 단기 입장 상태를 검증. 본문 API와 서버 렌더링은 게이트 전에 민감 본문을 내려주지 않는다. 재사용 토큰/다른 방 토큰/다른 계정 토큰 거절. 콘텐츠 요청은 no-store. 클라이언트 재생 검증의 한계 명시.
## 자동/수동 확인
재녹음 후 권한 초기화, 재생 도중 중단, 재생 오류, URL 직접 진입, 뒤로/앞으로, 새로고침, 다른 방에서 재입장, 계정 변경, 타 방 토큰. 실제 브라우저 녹음은 사용자 제스처와 마이크가 필요한 부분을 별도로 수동 확인 목록으로 남겨라.
