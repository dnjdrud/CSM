# 5단계 — 저장·개인글 암호화·관리자
기존 DB 조사 후 재사용. 없으면 단일 서버 개발용 SQLite 등 간단한 영속 저장을 선택하고 서버리스 운영 시 별도 영속 DB 필요를 README에 명시. 실제 저장을 구현하며 메모리 mock을 완성으로 보고하지 않는다.
## 모델
User(role mother/father/son), Session, Entry(owner, type private/shared, roomId, content 또는 ciphertext/encryptionMetadata), ConversationProposal(owner, method, proposedAt, timezone, location, companion, message, status), ContentDraft(검토/게시).
입장 음성 데이터 테이블은 만들지 않는다. 본문 입장 grant는 단기·세션별·방별로 설계하고 상시 녹음 면제 플래그 없음.
## 개인글
개인 비밀번호는 로그인 코드와 분리. 표준 Web Crypto 사용, 검증된 KDF 설정과 무작위 salt/nonce 및 인증 암호화(AES-GCM 등). 임의 암호 알고리즘 금지. 서버는 암호문만 저장. 비밀번호/키/평문을 로그·분석·서버 요청·초안 저장에 보내지 않는다. 탭 종료 시 키 제거. 본인에게만 암호문 접근 허용.
관리자에게 개인글 제목/원문을 노출하지 않는다. 개인정보 내용이 제목에 들어갈 수 있으므로 제목도 암호화. 비밀번호 분실 복구 불가 및 다른 기기 이용 방식 안내. 서버 운영자가 클라이언트를 바꿀 수 있는 위협까지 절대적 비밀 보장한다고 과장하지 않는다.
공개 범위 변경은 복호화 후 작성자가 별도 최종 확인한 경우만. 암호화 실패 시 평문 fallback 금지.
## 아들에게 전한 글
소유 부모와 아들만 조회/수정 권한 구분. 다른 부모 접근 거절. 소유자 편집·삭제. XSS 방지 및 텍스트 안전 렌더링. 길이 제한/유효성/CSRF 보호.
## 관리자
별도 인증. 공유글 목록과 개별 확인, 대화 제안 수락/다른 시간 제안/취소, 편지·카드 콘텐츠 초안 및 게시 관리. 부모 개인글 복호화/입장음성/감정 점수/체류시간/읽음 추적 없음.
전달 메시지는 아들이 준비되어 선택할 때 본문 표시. 답장 기능을 구현하면 부모의 해당 공유 대화에만 연결하며 외부 발송 금지.
확인: ID 조작, 계정 교차 조회, 개인글 DB 암호문, 로그 민감정보, 미인증 API, 암호 오류/손상 처리, 게시 전 초안 비노출.
